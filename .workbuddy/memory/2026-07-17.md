   - 运行中的 app 与 LS 记录的可信签名不匹配 → TCC 拒绝
2. **每次重新构建 CDHash 都变**：fix-tcc.sh 用 `cp` 替换二进制再重签，每次 CDHash 都不同，TCC 授权失效
3. **Apple Development 证书签名 + 未公证**：spctl 评估 rejected，macOS 26.3 (Tahoe) 对未公证应用 TCC 策略更严，"手动添加后立即消失"是已知现象

## 后续修复尝试（凌晨 00:44 - 01:00）

用户反馈：辅助功能列表仍找不到 app，手动添加也不行。

### 进一步排查
- 重启 tccd（`osascript with administrator privileges` 杀 tccd）→ 仍不行
- ad-hoc 签名 → 仍不行（spctl rejected）
- Hardened Runtime + entitlements 重新签名 → 仍不行
- `spctl --master-disable` → Tahoe 要求在系统设置确认，命令行直接执行被拒
- app 日志确认：app **确实在请求 TCC 权限**（`TCCAccessRequest() IPC` + `universalaccessAuthWarn`），但 tccd 不把 app 加入列表

### 核心结论
**macOS 26.3 (Tahoe) 对未公证应用的硬性限制**：Apple Development 证书签名的未公证应用，tccd 收到辅助功能请求但不加入列表，手动添加也被静默拒绝。spctl 评估永远 rejected。

### 最终方案尝试：osascript 命令行
- 修改 `ClipboardStore.swift`：`pasteViaAppleScript()` 改用 `Process()` 启动 `/usr/bin/osascript`（系统应用，已信任），权限归因于 osascript 而非 app
- `sendPasteKeystroke` 改为 `isAccessibilityTrusted(prompt: false)` 不弹窗，直接 fallback 到 osascript
- 重新构建 + 签名（不带 Hardened Runtime）+ 启动
- **用户未反馈结果**
